# Nova CRM — بسته توسعه مدیریت کاربران و سطح دسترسی

## موارد پیاده‌سازی‌شده در برنامه
- نام نمایشی اپلیکیشن اندروید: **Nova CRM**
- ورود کاربران موجود با نام کاربری و رمز عبور از طریق Edge Function امن `username-login`؛ رمز عبور به‌صورت مستقیم در دیتابیس ذخیره نمی‌شود.
- مدیر از صفحه «مدیریت کارکنان» کارمند جدید را با نام، نام کاربری، ایمیل و شماره تماس دعوت می‌کند.
- کارمند از لینک دعوت ایمیلی به صفحه فعال‌سازی می‌رود و خودش رمز عبور را انتخاب می‌کند.
- دکمه‌های افزودن/ویرایش/حذف پرونده، ثبت پرداخت و خروجی CSV فقط برای مدیر فعال‌اند.
- کارمند سوابق پزشکی را نمی‌بیند؛ اطلاعات پزشکی به جدول جداگانه مدیرمحور منتقل شده است.
- محدودیت نوشتن روی پرونده‌ها و پرداخت‌ها در trigger سمت دیتابیس نیز اعمال می‌شود، نه فقط در رابط کاربری.

## بسیار مهم: یک مرحله تنظیم سمت Supabase لازم است
این ZIP به‌تنهایی نمی‌تواند تنظیمات پروژه Supabase شما را از راه دور تغییر دهد. برای فعال شدن قابلیت‌ها، مراحل زیر را یک‌بار انجام بده:

### 1) پشتیبان‌گیری و اجرای Migration
1. قبل از هر تغییر از دیتابیس Supabase بکاپ بگیر.
2. فایل `supabase/migrations/202611090001_nova_crm_security.sql` را در SQL Editor داشبورد Supabase اجرا کن.
3. اجرای موفق را بررسی کن. این migration ستون `medical_history` را از `customers` به جدول مجزای `customer_medical_records` منتقل و از جدول اصلی حذف می‌کند. دسترسی جدول پزشکی فقط برای مدیر فعال است.
4. برای مدیر فعلی، نام کاربری اولیه از ابتدای ایمیل ساخته می‌شود. نام کاربری نهایی را با کوئری زیر بررسی/تنظیم کن:

```sql
select id, email, username, role from public.profiles;

-- در صورت نیاز نام کاربری مدیر را تغییر بده:
update public.profiles
set username = 'admin'
where email = 'YOUR_ADMIN_EMAIL';
```

نام کاربری باید یکتا باشد و فقط از حروف انگلیسی کوچک، عدد، نقطه، خط تیره و زیرخط استفاده کند.

### 2) میزبانی صفحه انتخاب رمز
فایل `activation/index.html` را روی یک آدرس HTTPS عمومی میزبانی کن؛ برای نمونه در یک وب‌سایت یا هاست استاتیک خودت. سپس آدرس کامل همان صفحه را نگه دار. این صفحه با لینک دعوت Supabase نشست را فعال می‌کند و به کارمند اجازه می‌دهد رمز خودش را انتخاب کند.

در Supabase → Authentication → URL Configuration:
- Site URL را به دامنه اصلی سایت خودت تنظیم کن.
- آدرس کامل صفحه فعال‌سازی را به Redirect URLs اضافه کن.

### 3) استقرار Edge Functions
Supabase CLI را روی کامپیوتر نصب کن، در ریشه پروژه Supabase login و link انجام بده، سپس:

```bash
supabase functions deploy username-login --no-verify-jwt
supabase functions deploy admin-create-user
```

برای تابع `admin-create-user` مقدار متغیر زیر را تنظیم کن:

```bash
supabase secrets set NOVA_ACTIVATION_URL="https://YOUR-DOMAIN.example/activation/"
```

کلید `service_role` فقط در محیط امن Edge Functions استفاده می‌شود و نباید داخل APK یا `config.js` قرار بگیرد.

### 4) ساخت نسخه اندروید
پوشه پروژه را در AIDE باز کن و `assembleDebug` یا Build APK را اجرا کن. ظاهر اصلی وب‌اپ حفظ شده است؛ فقط کنترل‌های دسترسی و فرم مدیریت کاربران اضافه شده‌اند.

## نکته سازگاری و بررسی
ساختار اولیه ZIP فقط کد اپلیکیشن و تنظیمات اتصال را داشت و فایل schema اصلی دیتابیس داخل آن نبود. بنابراین migration بالا بر اساس نام جدول‌ها و ستون‌هایی نوشته شده که خود برنامه استفاده می‌کند (`profiles`, `customers`, `payments`). قبل از اجرای روی داده واقعی حتماً بکاپ بگیر و اگر ساختار دیتابیس تو با این ستون‌ها تفاوت دارد، migration باید با schema واقعی تطبیق داده شود.

## نسخه بازبینی‌شده Migration
فایل `supabase/migrations/202611090001_nova_crm_security.sql` در این نسخه بازبینی شده است و علاوه بر محدودیت‌های مشتری/پرداخت/پزشکی، سیاست‌های پروفایل و RPCهای مورد استفاده رابط کاربری را نیز پوشش می‌دهد.

هشدار: کاربر تصمیم گرفته بدون تهیه بکاپ ادامه دهد. اجرای Migration روی دیتابیس واقعی همچنان ریسک دارد. این اسکریپت ستون `customers.medical_history` را پس از انتقال داده‌ها به `customer_medical_records` حذف می‌کند. اجرای آن را فقط در صورتی انجام بده که جدول‌ها و ستون‌های پروژه با پیش‌نیازهای اسکریپت منطبق باشند. اسکریپت در یک تراکنش اجرا می‌شود؛ اگر خطایی رخ دهد، دستورات همان اجرا rollback می‌شوند.

پس از اجرای موفق Migration:
1. مقدار `username` مدیر را بررسی و در صورت نیاز تنظیم کن.
2. صفحه `activation/index.html` را روی HTTPS میزبانی کن.
3. مقدار `NOVA_ACTIVATION_URL` را در Secrets تابع `admin-create-user` برابر آدرس کامل صفحه فعال‌سازی قرار بده.
4. توابع Edge را آزمایش کن؛ تا قبل از این مراحل، دعوت کارمند و ورود با نام کاربری را آزمایش نکن.
